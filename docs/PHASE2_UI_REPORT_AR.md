# Phase 2 — الجزء الثاني: ربط الواجهات بالباركود الهجين

## الحالة
تم تنفيذ تغييرات الواجهة محلياً فقط. لم يُنفّذ Deploy على Vercel، ولا Push أو Commit، ولا أي Migration أو كتابة على قاعدة Live في هذا الجزء. التعديلات المحلية السابقة محفوظة.

## الكاشير
- كتالوج POS يجلب product_barcodes ضمن المنتج ويحفظها مع بيانات الكتالوج عبر مسار IndexedDB الموجود؛ lib/local-db.js لم يحتج تغييراً جديداً.
- أثناء الاتصال، scanBarcode يستعلم product_barcodes بمطابقة barcode وtenant_id. الاستجابة الفارغة من الخادم لا تعيد إحياء رمز محذوف من الكاش. عند انقطاع الشبكة تستخدم الخريطة المحلية.
- باركود الموديل يفتح BarcodeModelPicker باستعمال CustomSelect الداكن ذي الدرج المنزلق. اللون والمقاس فارغان أولياً؛ لا إضافة تلقائية حتى لو كانت هناك تركيبة واحدة. التأكيد الصريح يضيف التركيبة المحددة فقط.
- باركود التركيبة والرموز البديلة يحددان variant_id مباشرة، وUUID يظل fallback بعد أولوية سجل الباركود. الكاش القديم الذي يفتقد خريطة الجدول الجديد يظل يدعم العمود legacy؛ الكاش الجديد ذو خريطة فارغة لا يستخدم رمزاً قديماً محذوفاً كبديل.
- حساب المتاح والحد الأقصى: quantity - reserved_qty عبر helper Phase1. المسحة الرابعة لحالة10/7 مرفوضة بالرسالة العربية الحالية.
- فحص سياق المؤسسة والفرع عند المسح والتأكيد، وحارس للعملية المتزامنة. المستمع HID الحالي مستعمل دون تغيير خوارزمية التقاطه. البيع المحلي يبقى Draft وفق Phase1.

## إضافة المنتج
- استُبدلت طلبات insert المتفرقة للمنتج/التركيبات/المخزون باستدعاء engine_create_product_atomic واحد.
- حقل باركود الموديل اختياري؛ لا يُولد عند فتح النموذج تلقائياً. التوليد اليدوي للموديل يظل متاحاً.
- حقول باركود تركيبـة اختياريـة لكل خلية لون/مقاس ذات كمية، مع دعم HID والكاميرا. الحقل الفارغ يرسل قائمة رموز فارغة كي يولد SQL الرمز داخل المعاملة.
- لا تحويل للرمز إلى رقم؛ الحفاظ على الأصفار البادئة. فحص المحارف/الطول والتكرار بين الرموز المدخلة قبل الإرسال.
- تغيير نوع المقاس يمسح رموز التركيبات المؤقتة مع كميات المصفوفة لتجنب نسبتها إلى نوع مختلف.
- منع النقر المتكرر أثناء الحفظ، وإبقاء النموذج عند الفشل. فشل الاستجابة الشبكية غير الحاسم يقفل إعادة الإرسال ويطلب مراجعة القائمة أولاً؛ لا توجد إعادة محاولة تلقائية لعملية الإنشاء.
- تبقى الحقول الإلزامية للتاجر الصورة/اللون/المقاسات/الكمية. الاسم والوصف يولدان كما سابقاً، والسعر الفارغ يرسل0.
- لم نعد ننشئ SKU من اسم المنتج المختصر، تجنباً للتصادم مع القيد العالمي الموجود؛ RPC يترك SKU غير المحدد NULL.
- رفع الصور إلى Storage يسبق RPC وليس جزءاً من معاملة SQL؛ لم ندّع ذرّيته. لا تحذف صورة تلقائياً بعد استجابة شبكية مبهمة قد يكون الحفظ معها قد اكتمل.

## طباعة الملصقات
- تقرأ product_barcodes للمؤسسة والمنتج، والتركيبات المربوطة بمخزون الفرع.
- CustomSelect بثلاثة خيارات: الموديل/التركيبة/كلاهما. جميع الرموز البديلة المحفوظة تظهر ضمن النوع المختار.
- تُطبع قيم قاعدة البيانات دون تعديل أو توليد أو إعادة حفظ. ثباتها مفروض في قاعدة البيانات من الجزء الأول ولا توجد خانة تعديل في شاشة الطباعة.
- fallback UUID لتركيبة بلا رمز مسجل. غياب رمز الموديل يظهر حالة فارغة ويعطل الطباعة بدلاً من طباعة تركيبة بالخطأ.
- CODE128 بمكتبة jsbarcode، تنسيق A4 الموجود، عدد نسخ صحيح1..50؛ زر الطباعة ينتظر جاهزية كل SVG/نسخة. لا تغيير لطباعة إيصالات58/80mm.

منها 10 اختبارات تفاعلية تُرندر الشاشات الفعلية في React + JSDOM + Testing Library، مع حد اتصال Supabase تجريبي:
1. HID الفعلي يستدعي scanBarcode ويفتح اختيار الموديل لتركيبة واحدة دون إضافة حتى اختيار اللون والمقاس وتأكيدهما.
2. باركود التركيبة يضاف مباشرة، والرابعة في حالة10/7 تُرفض.
3. الطباعة تتنقل بين الموديل/التركيبة/كليهما عبر CustomSelect وتستدعي window.print دون كتابة باركود.
4. حفظ المنتج يستدعي RPC مرة واحدة ويحافظ على باركود الموديل ورمز التركيبة ذي الأصفار البادئة.
5. خطأ RPC يبقي المدخلات ويعيد تفعيل الحفظ.
6. UUID يعمل بعد استجابة سجل فارغة.
7. إلغاء اختيار الموديل لا يضيف سطراً.
8. تكرار رمز الموديل/التركيبة يُرفض قبل RPC.
9. استجابة شبكة مبهمة تقفل إعادة الإرسال وتبقي المسودة.
10. غياب رمز الموديل يعطل الطباعة، وعدد النسخ الكسري يتحول لعدد صحيح.

7 اختبارات منطق/IndexedDB إضافية تغطي aliases وLegacy وأولوية السجل على UUID وعزل المؤسسة وعدم إحياء الرموز المحذوفة، وبناء payload، وأنواع الملصقات، وحفظ خريطة الرموز دون إنترنت ورفض4/قبول3 كمسودة عند كمية10/محجوز7.

أضيفت esbuild وjsdom و@testing-library/react كاعتماديات تطوير للاختبارات/المعاينة فقط. لا إدخال لها في حزمة الإنتاج الخاصة بالتطبيق.
